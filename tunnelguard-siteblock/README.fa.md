# مسدودسازی سایت‌ها روی سرور — افزونهٔ TunnelGuard

[English](README.md)

با این افزونه می‌توانید **اینستاگرام، یوتیوب، توییتر/X، سایت‌های غیراخلاقی** و هر دامنهٔ دلخواه دیگری را روی سرور ببندید. این افزونه کاملاً مستقل است:

- هیچ فایل یا سرویس TunnelGuard را تغییر نمی‌دهد و چیزی از آن import نمی‌کند.
- فقط زنجیره‌های iptables خودش (`TG_SITEBLOCK`، `TG_SB_*`)، یک فایل تنظیمات و یک سرویس systemd جدا می‌سازد.
- با «حذف کامل» هیچ اثری از آن باقی نمی‌ماند.

## روی کدام سرور نصب شود؟

**روی سرور خارج (نقش ۲).** ترافیک کاربران از این سرور به اینترنت می‌رود. در سرور ایران فقط ترافیک رمزشدهٔ تانل دیده می‌شود و فیلتر آنجا روی کاربران اثری ندارد. منوی افزونه نقش سرور را تشخیص می‌دهد و اگر روی ایران نصب شده باشد هشدار می‌دهد.

## نصب

پیش‌نیاز: Ubuntu با systemd، دسترسی root، Python 3.11+ و iptables. همهٔ این‌ها با گزینهٔ **۵** منوی `setup.py` نصب می‌شوند.

فایل `site_block.py` را روی سرور خارج کپی کنید، مثلاً داخل پوشهٔ TunnelGuard. بعد:

```bash
sudo python3 site_block.py install
```

این فرمان:
- برنامه را در `/opt/tunnelguard-siteblock` کپی می‌کند،
- سرویس `tunnelguard-siteblock` را می‌سازد تا قوانین بعد از ری‌استارت هم برقرار بمانند،
- فرمان کوتاه `tg-siteblock` را اضافه می‌کند.

از این به بعد برای باز کردن منو:

```bash
sudo tg-siteblock
```

## فرمان‌های بدون منو

```bash
sudo tg-siteblock enable instagram youtube twitter porn
```

```bash
sudo tg-siteblock disable youtube
```

```bash
sudo tg-siteblock add tiktok.com snapchat.com
```

```bash
sudo tg-siteblock remove snapchat.com
```

```bash
sudo tg-siteblock off
```

```bash
sudo tg-siteblock on
```

```bash
sudo tg-siteblock status
```

```bash
sudo tg-siteblock check www.instagram.com
```

```bash
sudo tg-siteblock uninstall
```

- `off` قوانین را برمی‌دارد ولی تنظیمات را نگه می‌دارد.
- `check` نشان می‌دهد یک دامنه مسدود است یا نه، و دلیلش را می‌گوید.
- `uninstall` قوانین، سرویس، فرمان و تنظیمات را کامل حذف می‌کند.
- `tg-siteblock rules` فقط قوانین تولیدشده را چاپ می‌کند و هیچ تغییری نمی‌دهد.

## چطور کار می‌کند

نام سایت در بخش‌های رمزنشدهٔ شروع هر اتصال شناسایی می‌شود. فقط ۸ کیلوبایت اول هر اتصال بررسی می‌شود تا بار پردازنده کم بماند.

| ترافیک | چه چیزی بررسی می‌شود | نتیجه |
|---|---|---|
| HTTPS (TCP 443) | نام سایت (SNI) در شروع TLS | قطع فوری اتصال |
| HTTP (TCP 80) | هدر Host | قطع فوری اتصال |
| DNS (پورت 53) | نام پرسیده‌شده | رد درخواست |
| QUIC (UDP 443) | نام قابل خواندن نیست | رد شدن؛ مرورگر و برنامه به TCP برمی‌گردند |

- قوانین در `OUTPUT` (ترافیک x-ui/Xray، sing-box و تانل‌های همین سرور) و `FORWARD` (ترافیک مسیریابی‌شده مثل WireGuard/GRE) قرار می‌گیرند. یعنی برای همهٔ برنامه‌های سرور اعمال می‌شوند، نه فقط یک پنل.
- ترافیک loopback (`lo`) بررسی نمی‌شود.
- اتصال‌های داخلی بین ایران و خارج (پورت‌های تانل) دست نمی‌خورند.
- IPv4 و IPv6 هر دو فیلتر می‌شوند (اگر `ip6tables` موجود باشد).

## محدودیت‌ها — حتماً بخوانید

- **بستن QUIC همهٔ سایت‌ها را شامل می‌شود.** HTTP/3 همهٔ سایت‌ها بسته می‌شود و آن‌ها بی‌صدا به HTTP/2 برمی‌گردند. اگر نخواهید، گزینهٔ ۷ را خاموش کنید. در آن حالت یوتیوب و اینستاگرام از طریق QUIC ممکن است باز بمانند. اگر Hysteria2 را روی پورت 443 همین سرور به‌عنوان **مقصد خروجی** دارید، این گزینه را خاموش کنید.
- **دور زدن ممکن است.** کاربری که از ECH (رمزگذاری نام سایت)، یک VPN دیگر داخل سرویس شما، یا ClientHello تکه‌تکه‌شده استفاده کند، ممکن است فیلتر را دور بزند. این ابزار برای کاربران معمولی کافی است، ولی مسدودسازی ۱۰۰٪ تضمین نمی‌شود.
- **لیست پورن کامل نیست.** کلمه‌های کلیدی مثل `porn`، `xvideos` و `hentai` بیشتر سایت‌ها را می‌گیرند، به‌علاوهٔ حدود ۵۰ دامنهٔ شناخته‌شده و پسوندهای `.xxx`، `.adult` و `.sex`. سایت جاافتاده را با «افزودن دامنه دلخواه» اضافه کنید.
- **عکس و ویدئوی اینستاگرام** بخشی روی `fbcdn.net` (مشترک با فیسبوک و واتس‌اپ) است. این دامنه عمداً بسته نشده تا واتس‌اپ خراب نشود. برنامهٔ اینستاگرام با بستن `instagram.com` و `cdninstagram.com` از کار می‌افتد.
- **تطبیق، بخشی از متن را می‌گیرد.** اگر سایت سالمی اشتباهی بسته شد (نادر است)، با گزینهٔ ۸ دلیلش را ببینید.
- **بعد از بازسازی فایروال، دوباره اعمال کنید.** اگر ابزار دیگری (مثلاً بازسازی کامل فایروال) زنجیرهٔ `OUTPUT` را پاک کرد، این را اجرا کنید:

```bash
sudo systemctl reload tunnelguard-siteblock
```

## فایل‌ها

| مسیر | توضیح |
|---|---|
| `/etc/tunnelguard-siteblock/config.json` | تنظیمات (دسترسی 600) |
| `/opt/tunnelguard-siteblock/site_block.py` | برنامهٔ نصب‌شده |
| `/etc/systemd/system/tunnelguard-siteblock.service` | سرویس اعمال قوانین هنگام بوت |
| `/usr/local/bin/tg-siteblock` | فرمان کوتاه |

## تست

```bash
python3 -m unittest -v test_site_block
```

این تست‌ها به root، اینترنت یا iptables نیاز ندارند.
