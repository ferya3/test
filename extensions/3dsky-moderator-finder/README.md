# 3dsky Moderator Finder

افزونه‌ی Chrome برای اینکه موقع آپلود مدل در **3dsky.org** ببینید مدل شما دست کدام مدیتور افتاده.

> ⚠️ **وضعیت صادقانه:** این افزونه هنوز روی خود 3dsky آزمایش نشده (سایت از محیط توسعه قابل دسترس نبود).
> روی یک سایت ساختگی محلی با Chromium واقعی تست شده و کار می‌کند، ولی اینکه 3dsky الان اطلاعات مدیتور را
> **اصلاً برای مرورگر شما می‌فرستد یا نه** فقط با اجرا روی سایت واقعی معلوم می‌شود. اگر سایت این اطلاعات را
> فقط روی سرور نگه دارد، هیچ افزونه‌ای نمی‌تواند آن را ببیند؛ در این حالت افزونه دقیقاً همین را به شما می‌گوید
> (تب «کد سایت») و خروجی JSON می‌دهد تا بشود راه بعدی را پیدا کرد.

## نصب (۱ دقیقه)

1. در Chrome آدرس `chrome://extensions` را باز کنید.
2. **Developer mode** (بالا سمت راست) را روشن کنید.
3. **Load unpacked** را بزنید و همین پوشه (`3dsky-moderator-finder`) را انتخاب کنید.
4. صفحه‌ی 3dsky را باز کنید (یا اگر باز بود، Refresh کنید). پایین-چپ صفحه یک قرص کوچک «مدیتور: هنوز پیدا نشد» می‌بینید.

## طرز استفاده

1. صفحه‌ی آپلود را باز کنید و مدل را آپلود کنید، **قبل از Submit نهایی** هم صفحه را باز نگه دارید.
2. قرص پایین-چپ را نگاه کنید:
   - 🟢 **سبز** با اسم/شناسه = مدیتور پیدا شد.
   - 🟠 **نارنجی** = فیلد مدیتور در پاسخ سایت هست ولی هنوز خالی (معمولاً بعد از پردازش مدل پر می‌شود؛ پنل را باز نگه دارید).
   - ⚪ **خاکستری** = تا الان چیزی دیده نشده.
3. روی قرص کلیک کنید تا پنل باز شود (یا روی آیکن افزونه در نوار ابزار).
4. اگر سایت فقط **شناسه‌ی** مدیتور را می‌دهد (مثلاً `moderator_id: 7`)، روی «اسم‌گذاری روی این مدیتور» بزنید و اسم او را بنویسید؛
   افزونه از آن به بعد اسم را نشان می‌دهد. با چهار مدیتور، بعد از چند آپلود نقشه‌ی کامل را دارید.

## افزونه از کجا اطلاعات می‌گیرد

همه‌ی این‌ها **روی مرورگر خودتان** و فقط روی `*.3dsky.org` اجرا می‌شود:

| منبع | چه چیزی را بررسی می‌کند |
|---|---|
| fetch / XHR | بدنه‌ی درخواست و پاسخ و هدرهای پاسخ (JSON، فرم، فریم socket.io، JSON تودرتو) |
| WebSocket / SSE | پیام‌های ورودی و خروجی |
| State صفحه | `__NUXT__`، `__NEXT_DATA__`، `__INITIAL_STATE__` و تگ‌های `<script type=application/json>` |
| DOM | متن، attributeها، المان‌های **مخفی** و کامنت‌های HTML |
| کد سایت (تب «کد سایت») | فایل‌های JS سایت را می‌خواند و دنبال اندپوینت/کدِ جامانده‌ی مربوط به moderator می‌گردد |

کلیدهایی مثل `moderator`، `moderator_id`، `assignedModerator`، `модератор` و … «مدیتور» حساب می‌شوند؛
`moderation_status` «وضعیت بررسی» است؛ `reviewer`/`curator`/`assigned_to` و مشابه، «سرنخ ضعیف» (پیش‌فرض مخفی؛ با تیک «سرنخ‌های ضعیف» نمایش داده می‌شود).

## اگر چیزی پیدا نشد

1. تب **«کد سایت»** → «اسکن کد سایت» (روی صفحه‌ی آپلود). اگر هیچ ردپایی از moderator در JS نیست، یعنی این بخش از فرانت‌اند حذف شده است.
2. تیک **«ثبت کامل بدنه‌ها»** را بزنید، یک آپلود دیگر انجام دهید، بعد تب **«لاگ شبکه»** را نگاه کنید (روی هر ردیف کلیک کنید تا بدنه باز شود).
3. **«خروجی JSON»** را بزنید و فایل را برای بهبود افزونه بفرستید. قبل از فرستادن بازش کنید و بررسی کنید چیز شخصی در آن نباشد.

## حریم خصوصی و امنیت

- هیچ داده‌ای به بیرون ارسال نمی‌شود؛ افزونه هیچ درخواست شبکه‌ای به سرور دیگری ندارد (به‌جز دانلود فایل‌های JS همان صفحه، که خود سایت لودشان می‌کند، وقتی دکمه‌ی «اسکن کد سایت» را بزنید).
- هدرهای **درخواست** (کوکی، توکن، Authorization) هرگز ثبت نمی‌شوند.
- یافته‌ها فقط در `chrome.storage.local` همین مرورگر ذخیره می‌شوند؛ «پاک کردن» همه را حذف می‌کند.
- افزونه رفتار صفحه را تغییر نمی‌دهد؛ فقط نظاره می‌کند.

## یک نکته

3dsky این اطلاعات را عمداً از صفحه‌ی آپلود برداشته است. بررسی کنید که لغو و آپلود مجدد برای انتخاب مدیتور با قوانین سایت
(و ریسک حساب کاربری‌تان) جور باشد؛ مسئولیت استفاده با خود شماست.

## ساختار فایل‌ها

```
manifest.json    تنظیمات MV3 (فقط *.3dsky.org)
hook.js          داخل جهان JS خود صفحه: شنود fetch/XHR/WebSocket/SSE و state
detect.js        موتور تشخیص مدیتور (بدون وابستگی به مرورگر؛ تست‌پذیر)
content.js       اسکن DOM، ذخیره‌سازی و پنل
background.js    نشان روی آیکن + اسکن کد سایت
test/            تست واحد (node) و تست end-to-end روی سایت ساختگی (Playwright + Chromium)
```

## تست

```bash
node test/detect.test.mjs        # تست موتور تشخیص
xvfb-run -a node test/e2e.mjs    # لود افزونه در Chromium واقعی روی یک سایت ساختگی محلی
```
