# پایداری تانل — افزونهٔ TunnelGuard

[English](README.md)

این افزونه دو کار انجام می‌دهد:

1. **نگهبان خودکار:** تانل‌های گیرکرده را پیدا می‌کند و خودکار ری‌استارت می‌کند.
2. **بهینه‌سازی شبکه:** تنظیمات کرنل را برای تانل‌های طولانی و شبکه‌های پرافت بهتر می‌کند. این تغییر کاملاً برگشت‌پذیر است.

هیچ فایلی از TunnelGuard تغییر نمی‌کند. افزونه فقط فایل‌های لینک‌ها را می‌خواند و سرویس‌های موجود `tunnelguard-link-*` را ری‌استارت می‌کند.

## چرا لازم است؟

در TunnelGuard هر لینک یک سرویس systemd است. systemd فقط وقتی سرویس را دوباره راه می‌اندازد که پروسه **کرش کند**. ولی رایج‌ترین مشکل در شبکه‌های ایران این است که پروسه زنده بماند و ترافیک رد نشود. دلیلش می‌تواند timeout در NAT، افت بسته، قطع اتصال توسط DPI، یا گیر کردن کلاینت در انتظار طولانی برای اتصال دوباره باشد (Chisel تا ۵ دقیقه صبر می‌کند). در این حالت تانل تا وقتی دستی ری‌استارتش نکنید قطع می‌ماند. پنل هم فقط وقتی تست می‌کند که دکمهٔ «تست» را بزنید.

## نگهبان خودکار چطور کار می‌کند

| سرور | بررسی | فاصله |
|---|---|---|
| **ایران** | برای هر لینک یک درخواست HTTP واقعی از پورت SOCKS همان لینک می‌فرستد. درخواست از تانل و سرور خارج رد می‌شود و به اینترنت می‌رسد. این بررسی برای همهٔ روش‌ها و هر دو جهت انجام می‌شود. | هر ۲۰ ثانیه |
| **خارج** | برای لینک‌هایی که خارج شروع‌کنندهٔ اتصال است (جهت معکوس روی SSH، Chisel، Rathole، IPIP، GRE و VXLAN) بررسی می‌کند که اتصال به ایران برقرار باشد. | هر ۲۰ ثانیه |

- بعد از **۳ شکست پشت‌سرهم** (حدود یک دقیقه)، سرویس همان لینک ری‌استارت می‌شود.
- اگر مشکل ادامه پیدا کند، فاصلهٔ ری‌استارت‌ها دو برابر می‌شود: ۱، ۲، ۴ ... تا حداکثر ۱۵ دقیقه. پس قطعی واقعی اینترنت باعث ری‌استارت پشت‌سرهم نمی‌شود.
- بعد از ۱۰ دقیقه کار سالم، این فاصله به حالت اول برمی‌گردد.
- لینکی که تازه روشن شده (کمتر از ۶۰ ثانیه) یا در حال نصب و حذف از پنل است، دست نمی‌خورد.
- برای پایداری کامل، افزونه را **روی هر دو سرور** نصب کنید.

## بهینه‌سازی شبکه

| تنظیم | فایده |
|---|---|
| BBR + fq | سرعت و پایداری بهتر روی مسیرهای پرافت و پرتأخیر |
| `tcp_mtu_probing=1` | جلوگیری از گیر کردن اتصال وقتی بسته‌های بزرگ در مسیر گم می‌شوند |
| keepalive هر ۶۰ ثانیه | زنده نگه داشتن اتصال‌های بیکار در NAT و فایروال‌ها |
| `tcp_slow_start_after_idle=0` | افت نکردن سرعت بعد از چند ثانیه بیکاری |
| بافرهای بزرگ‌تر، صف اتصال بیشتر و `nf_conntrack_max` | تحمل کاربر و اتصال هم‌زمان بیشتر |

- مقدارهای قبلی ذخیره می‌شوند و با «برگرداندن تنظیمات» دقیقاً برمی‌گردند.
- بازهٔ پورت‌های موقت (`ip_local_port_range`) عمداً تغییر نمی‌کند، چون با پورت‌های ثابت TunnelGuard تداخل پیدا می‌کرد.

## نصب

فایل `stability.py` را روی **هر دو سرور** کپی کنید و روی هر کدام بزنید:

```bash
sudo python3 stability.py install
```

بعد برای باز کردن منو:

```bash
sudo tg-stability
```

اگر نمی‌خواهید تنظیمات کرنل تغییر کند، این را بزنید:

```bash
sudo python3 stability.py install --no-tune
```

## فرمان‌ها

```bash
sudo tg-stability status
```

```bash
sudo tg-stability check
```

```bash
sudo journalctl -u tunnelguard-stability -f
```

```bash
sudo tg-stability untune
```

```bash
sudo tg-stability uninstall
```

- `status` لینک‌ها، تعداد ری‌استارت‌ها و وضعیت سرویس را نشان می‌دهد.
- `check` همهٔ لینک‌ها را همین الان تست می‌کند، بدون ری‌استارت.
- با `journalctl` گزارش زندهٔ نگهبان را می‌بینید: کدام لینک قطع شد و کی ری‌استارت شد.
- `untune` تنظیمات شبکه را به حالت قبل برمی‌گرداند.
- `uninstall` همه‌چیز را حذف می‌کند، از جمله برگرداندن تنظیمات شبکه.

## تنظیمات

فایل `/etc/tunnelguard-stability/config.json`. بعد از تغییر این را بزنید:

```bash
sudo systemctl restart tunnelguard-stability
```

| کلید | پیش‌فرض | توضیح |
|---|---|---|
| `interval` | 20 | فاصلهٔ بررسی‌ها (ثانیه) |
| `timeout` | 10 | حداکثر زمان هر تست |
| `failures` | 3 | تعداد شکست پشت‌سرهم قبل از ری‌استارت |
| `grace` | 60 | مهلت بعد از روشن شدن لینک |
| `cooldown` / `max_cooldown` | 60 / 900 | فاصلهٔ اول و حداکثر بین ری‌استارت‌ها |
| `targets` | cp.cloudflare.com، gstatic | آدرس‌های تست (فقط `http://`). یکی جواب بدهد کافی است. |

## محدودیت‌ها

- **این افزونه شبکهٔ خراب را درست نمی‌کند.** اگر ارتباط ایران و خارج واقعاً قطع یا فیلتر شده باشد، ری‌استارت کمکی نمی‌کند. فقط وصل شدن دوباره بعد از رفع مشکل سریع‌تر می‌شود. در آن حالت از پنل روش یا جهت دیگری بسازید. TunnelGuard بین لینک‌های سالم خودش جابه‌جا می‌کند.
- در سرور خارج، لینک‌های WireGuard، Paqet و Spoof بررسی اتصال ندارند (حامل‌شان UDP یا raw است). نگهبان سمت ایران این لینک‌ها را با تست کامل پوشش می‌دهد.
- ری‌استارت لینک، اتصال‌های در جریان روی همان لینک را قطع می‌کند. برنامه‌ها خودشان دوباره وصل می‌شوند.
- نصب‌های قدیمی (Shadowsocks، Trojan و Hysteria2 با `deploy.py`) پوشش داده نمی‌شوند. فقط لینک‌های ساخته‌شده از پنل (نسخهٔ ۲.۵ به بعد) بررسی می‌شوند.
